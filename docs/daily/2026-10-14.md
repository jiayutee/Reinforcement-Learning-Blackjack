# 14 October: render observations, keep rules in the environment

## Prerequisites and intuition

The environment state contains private cards and authoritative balances. Its visible snapshot is an observation. Rendering means translating that observation into things you can see: card faces, the active hand and the result. Rendering should not choose actions, draw cards or calculate payouts.

The public-rule browser now shows rank/suit cards, a patterned hidden dealer card, separate hand sections and a highlighted active hand. Balance and completed round profit display in chips. The raw visible JSON remains available under “Inspect visible state” for learning and debugging. This is a local prototype, not the finished public game.

## Run it

```sh
python3 -m public_game.local_game --port 8766 --seed 7
```

Open http://127.0.0.1:8766, deal10 chips, then stand. Seed7 produces a loss: balance90 chips, profit-10 chips and normalized result-1. The dealer's patterned card becomes a face only after settlement. Stop the server with Ctrl-C.

## Code step by step

In [the page](../../public_game/local_game.html), `drawCards` creates elements from visible rank/suit records. A null card becomes a hidden-card placeholder, never a guessed rank. Each card has an accessible text label, so suit color is not the only information channel.

`drawTable` loops over all hands, highlights the index supplied by `active_hand`, and displays server-owned stakes/outcomes. Text is assigned with `textContent`, not interpreted as HTML. The existing command path still submits intents to the session. No game rules were added to JavaScript.

Unit conversion is presentation: displayed chips=internal units/2. For a loss of20 units on initial wager20, normalized result=-20/20=-1; displayed profit is-10 chips. The ratio remains unchanged. Refreshing the display is not an RL transition and must not produce another reward.
