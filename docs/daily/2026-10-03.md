# 3 October: let the frozen agent take one step

## Prerequisites and intuition

An observation describes what the agent sees; a policy chooses an action; the environment returns a reward and next observation. Review [frozen inference](2026-10-02.md) and [visible state and revisions](2026-10-01.md). Python functions and dictionaries are enough for today's code.

Advice says what the agent would do. A bot step executes that choice once. Keeping the steps separate makes the loop inspectable and prevents a timer or repeated request from unexpectedly playing an entire hand.

## The loop, one equation at a time

1. Observe oₜ = (player total, dealer upcard, usable ace).
2. Choose aₜ = argmaxₐ Q(oₜ,a), preferring stand on ties, but withhold the choice if either action lacks recorded evidence.
3. Execute the action in the environment: (oₜ₊₁,rₜ₊₁,done) = step(aₜ).
4. Leave Q unchanged: Q_after = Q_before. This is inference, not training.
5. Increase the session revision by one for the accepted command. Stop after this action, even if the hand continues.

A new action needs a new current observation and revision. A stale command must not be repeated automatically with a newer revision. Otherwise a network retry can become an unintended second hit.

## Worked example and code

The deterministic test fixture assigns Q(9,7,False,stand)=-0.4 and Q(9,7,False,hit)=0.2, with both actions visited. Hit wins the comparison. Seed 7 starts player [6,3], dealer [7,None]. One hit adds an ace, producing soft 20 and revision 2. The dealer hole card stays hidden. This synthetic fixture has no entry for soft 20, so the next action is withheld. It is a test of behavior, not trained-agent performance.

[apply_table_command](../../foundations/local_game.py) implements the boundary:

- For `bot`, validate the expected revision before obtaining advice.
- Obtain advice through `table_view`, which uses only visible information.
- Reject missing, terminal or unsupported advice without changing the session.
- Translate action 0/1 into stand/hit and call the same session command used for manual play.
- Return the updated view and its next-state advice. There is no automatic second action.

The HTTP handler now accepts `bot` through this dispatcher; the browser button is the next checkpoint. Existing manual commands keep working without a policy. The server remains single-threaded and local, so its check/update path is serialized. This is not a public multi-user service.

## Runnable experiment

From the project root, generate a full trained export if needed, then inspect one bot step in Python:

```sh
python3 -m foundations.q_learning --output /tmp/q-policy.json
python3 - <<'PYCODE'
from foundations.policy import load_policy
from foundations.session import GameSession
from foundations.local_game import apply_table_command
policy = load_policy('/tmp/q-policy.json')
session = GameSession(7)
print(apply_table_command(session, policy, 'deal', 0))
print(apply_table_command(session, policy, 'bot', 1))
PYCODE
```

A policy lacking both-action evidence for the current state raises a clear error instead of guessing. Do not reinterpret the earlier greedy-evaluation scores as measurements of this withholding behavior.
