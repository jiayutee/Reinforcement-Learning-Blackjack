# 2026-10-21 — keep wager controls in sync with the round

## 03:00 checkpoint: disable unavailable or mistimed wagers

### Prerequisites and intuition

The wager input uses whole chips. The public game snapshot stores the bankroll in half-chip units so that a 3:2 natural payout uses exact integer arithmetic. Quick wager buttons are only shortcuts; the Python session remains responsible for accepting or rejecting the wager.

During an active player hand, the initial wager is already fixed, so allowing the user to change the next-round wager is confusing. A preset that costs more than the current bankroll also cannot start a round and should be disabled.

### Equation and worked example

For a preset of `c` whole chips and a visible balance `B` in half-chip units:

```text
available(c, B) = (2 × c <= B)
```

If the snapshot balance is 20 half-chip units, that is 10 whole chips. Presets of 5 and 10 chips are affordable; 25 and 50 are not. While `phase == player_turn`, the wager input and all presets are disabled because the current round has already started. These browser affordances help users; the server still validates every Deal.

### Coding walkthrough

In [`local_game.html`](../../public_game/local_game.html), `render()` derives a lock from `busy`, missing state, or `player_turn`. It disables the wager field and presets while locked. Otherwise each preset compares its chip cost, converted to half-chip units, with the latest visible `state.balance`. The Deal handler and Python session validation remain unchanged.
