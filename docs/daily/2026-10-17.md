## 04:00 checkpoint: estimate state values with first-visit Monte Carlo

### Prerequisites and intuition

We have an **episode collector**: a complete round recorded as visible decision observations and actions, with its normalized profit attached only to the final transition. A **reward** is the feedback at one transition; a **return** is the total future reward from a decision onward. A **policy** is the rule choosing actions. Our threshold policy is fixed: hit below17, otherwise stand. No training or policy improvement is happening yet.

Monte Carlo (MC) prediction asks: “Under this particular policy, what average final profit follows a visible decision state?” It waits until the round ends, then uses the observed outcome as a sample. Like estimating a die's average by rolling it repeatedly, individual results are noisy; the sample mean becomes more informative as the state is revisited. It does not need a model of card probabilities or a Bellman equation.

### Return equation, one step at a time

For rewards `r_(t+1), ..., r_T`, the return from time `t` is

```text
G_t = r_(t+1) + gamma*r_(t+2) + gamma^2*r_(t+3) + ... + gamma^(T-t-1)*r_T
```

Here `gamma` is the discount factor between0 and1. We use `gamma=1` because this is an undiscounted finite blackjack round: an eventual chip is worth the same regardless of how many decisions it took. The collector puts reward0 on every intermediate action and the final normalized round profit on the last action. Thus, with `gamma=1`, each state visited in one round receives that round's final normalized profit as its return. Opening naturals are round outcomes with no player decision and are counted separately; they do not invent a state/action sample.

For contrast, if three rewards are `[0, 0, +1]` and `gamma=0.5`, working backward gives returns `[0.25, 0.5, 1]`: `G_2=1`, `G_1=0+0.5*1`, and `G_0=0+0.5*0.5`. This makes the discount exponents concrete; this blackjack experiment itself uses `gamma=1`.

### Worked sample-mean update

Suppose the same decision state `s` is encountered in two complete rounds. Its final returns are `+1` and `-1` initial wagers. The value estimate is

```text
V(s) = (1 + (-1)) / 2 = 0 initial wagers.
```

For a new return `G`, the incremental implementation is `V <- V + (G - V)/N`, where `N` is the new visit count. If the old mean is+1 from one visit and the new return is-1, then `V=1+(-1-1)/2=0`. Only the **first** occurrence of a state in each episode is used; if the same state appears again later in that round, it is not a second independent sample of the same completed outcome.

The state key is a deliberately compact feature bucket made from visible decision information: active hand total, usable-ace flag, dealer upcard rank, split context, number of hands, and the legal-action tuple. Rule profile and original wager are held fixed by this experiment. The bucket still omits the finite-shoe composition, bankroll, active hand's current stake, and the complete outcomes of earlier split hands. Consequently these are conditional averages for the selected features under this experiment's sampling distribution, not exact values for a fully represented Markov state. This is a useful limitation to notice before later control or strategy claims. Values are keyed by state, not by action: this predicts `V(s)` under the fixed policy; it is not `Q(s,a)` and does not choose a better action.

### Coding walkthrough and experiment

The implementation is in [monte_carlo.py](../../public_game/monte_carlo.py). `state_key` compresses the visible snapshot to a hashable tuple. `update` walks transitions backwards, accumulating `reward + gamma * running_return`; this is the return equation implemented from right to left. A set remembers states already seen in the current episode. The count-and-mean dictionary applies the incremental sample-average equation. The new `run_prediction` path reuses the fixed threshold policy and episode collector, then prints the most visited observed states; `--top 0` prints all observed estimates.

Run:

```sh
python3 -m public_game.experiment --predict --episodes 1000 --seed 7 --top 8
```

### Limitations and exercise

This estimates values for a single fixed, simplistic policy, not an optimal policy. Only visited states receive estimates; after1,000 rounds, the mean count among446 keys is still low and rare split states are especially sparse. The coarse state key omits relevant game context, and a persistent shoe adds hidden state and dependence across rounds; estimates should be read as conditional averages under this policy and sampling setup. The policy ignores usable aces and pairs. An `MC` estimate says what tends to happen under that policy—not the probability of winning a specific hand and not the result of taking each possible action. A control method must additionally estimate action values, explore alternatives, and improve its policy; that is a later lesson.
