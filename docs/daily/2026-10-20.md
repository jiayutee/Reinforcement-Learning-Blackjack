# 2026-10-20 — test a disclosure without a mouse

## 03:00 checkpoint: keyboard operation of Game rules

### Prerequisites and intuition

The public table uses the browser's native `<details><summary>` disclosure for its rules. Native controls provide familiar keyboard behavior, but we should verify the behavior the game depends on rather than assume it.

### Small state model and worked check

Treat the disclosure as a two-state UI:

```text
closed --focus summary, press Enter--> open
open   --press Space on summary-----> closed
```

The browser test reads the element's `open` property after each key. It also checks that all six rules are available while open. This is separate from blackjack's game state: opening the help panel should not change the session revision, hand, balance or sound.

### Coding walkthrough and runnable experiment

In [`tests/browser/public-game.cjs`](../../tests/browser/public-game.cjs), the test focuses `#rules summary`, sends Enter, checks `details.open`, reads the text, then sends Space and checks that it is closed again. The tested control is the native disclosure in [`public_game/local_game.html`](../../public_game/local_game.html); no custom keyboard handler is necessary.

Run from the repository root:


All three Chrome journeys passed: manual, split, and soft-ace. The rules disclosure opened and closed by keyboard, and the checks reported no JavaScript page errors. This verifies keyboard behavior in installed Chrome; it is not a complete browser or screen-reader audit.

## 04:00 checkpoint: quick whole-chip wager buttons

### Prerequisites and intuition

The wager is entered in whole chips, while the Python contract stores half-chip units so 3:2 naturals are exact integers. A few common wager buttons reduce typing on a small screen; the existing input remains available for any other positive whole-chip amount.

### Worked unit conversion

Choosing the 25-chip preset only sets the input to `25`; it does not start a round. On Deal, the existing handler sends `stake = chips × 2`, so 25 chips becomes 50 half-chip units. The backend still checks the wager against the balance and current game phase.

### Coding walkthrough and experiment

The [wager controls](../../public_game/local_game.html) use native `type="button"` elements with `aria-pressed`. Clicking a preset updates the text input and selected state; editing the input updates which preset (if any) is selected. No wager choice changes the server session. The [browser test](../../tests/browser/public-game.cjs) selects 25 with Enter, confirms the input and pressed states, verifies revision remains 0, edits back to 10, and checks that an invalid custom value clears all selected presets.

Run the same Chrome command above in this lesson. Result: all three browser journeys passed, including preset synchronization; all 146 Python tests and `git diff --check` passed.
