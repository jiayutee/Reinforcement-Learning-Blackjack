# 6 October: a finite shoe changes the state

## Prerequisites and intuition

A rank is A, 2,…,10,J,Q,K; a suit is clubs, diamonds, hearts or spades. One deck has 13×4=52 cards. A shoe combines decks. Probability for a uniformly random remaining card is favorable remaining cards divided by all remaining cards. Review [the agent/environment lesson](../lessons/01-agent-environment.md) if observations and internal state are unfamiliar.

The Foundations learner draws with replacement, so its rank probabilities stay fixed. A real finite shoe removes each drawn card. We now have a **separate building block** for that future game; the current browser and trained agents still use Foundations rules.

## Counts and worked probabilities

One deck has four cards of each rank, one per suit. Six decks have 24 of each rank and six copies of each rank/suit combination. Initial shoe size = 6×52 = **312**.

Ten-valued ranks are 10,J,Q,K. Initial ten-valued count = 4 ranks×4 suits×6 decks = **96**.

1. Before any draw, P(ten-valued) = 96/312 = 4/13, about 0.307692.
2. After removing a known ten-valued card, count becomes 95 and size 311.
3. P(next ten-valued | that removal) = 95/311, about 0.305466.
4. If instead an ace was removed, ten-valued count stays 96: 96/311, about 0.308682.

These conditional probabilities assume the remaining cards are otherwise unknown and uniformly shuffled. Exact shoe composition belongs to the environment; a player does not automatically know unseen removals such as a dealer hole card.

## What this changes for RL

A Markov state contains enough information to predict the next-state/reward distribution given the action, without needing earlier history. With replacement, our compact learning observation is useful for the simplified benchmark. In a finite shoe, two histories can lead to the same `(total, upcard, usable ace)` but different remaining-card distributions. Reusing the compact observation does not magically make finite-shoe play fully observed.

Later options include additional observed history/count features or a belief about hidden composition. Giving the agent the exact private shoe would instead give it information the human does not have. Do not feed the new shoe to existing agents and describe their old evaluation as rule-compatible evidence.

## Code walkthrough

[public_game/cards.py](../../public_game/cards.py) is separate from Foundations:

- Immutable `Card(rank,suit)` preserves real identity. `value` maps face ranks to 10 and ace to 1; hand scoring later decides whether an ace can count as 11.
- `Shoe` builds the declared number of decks, then shuffles with its own seeded generator.
- `draw()` pops one card, reducing remaining count by one. It never silently refills.
- `needs_shuffle` checks consumed/initial >= penetration. The preview default is 75%.
- `prepare_round()` rebuilds only when that threshold has been crossed. Its caller must invoke it **between** rounds; this primitive has no round state and cannot enforce that lifecycle itself.

For six decks at 75%, the threshold is 312×0.75=234 consumed cards, leaving 78. Crossing the threshold mid-hand does not trigger a draw-time shuffle. The future full engine must manage round boundaries and ensure sufficient cards for permitted splits/doubles; this primitive alone does not prove that complete-game requirement.

## Runnable experiment

```sh
python3 - <<'PYCODE'
from collections import Counter
from public_game.cards import Shoe
shoe = Shoe(decks=6, seed=7)
cards = [shoe.draw() for _ in range(312)]
print('Cards:', len(cards))
print('Each rank:', dict(sorted(Counter(c.rank for c in cards).items())))
print('Ten-valued:', sum(c.value == 10 for c in cards))
print('Remaining:', shoe.remaining)
try:
    shoe.draw()
except RuntimeError as error:
    print(error)
PYCODE
```

Expected: 312 cards, 24 per rank, 96 ten-valued, zero remaining, then an exhaustion error. A seed makes this experiment reproducible; it must not become a public player's way to predict hidden cards in a deployed game.

## 04:00 checkpoint: equal totals can mean different hands

Added [public hand facts](../../public_game/hands.py), reusing the tested ace arithmetic from Foundations while preserving rank and split context. It reports total, usable ace, bust, natural and equal-rank pair. It does not settle wagers or decide legal actions.

A natural requires exactly two cards totalling 21 in an unsplit hand. A+K qualifies; 7+7+7 does not. A+K after splitting also does not qualify under the proposed public rules, although its total remains 21. This is why the compact RL observation `(total, upcard, usable ace)` is insufficient by itself for public-game payouts and legal actions.

Worked scoring: A+A+9 starts at 1+1+9=11; promote one ace by 10 to reach 21. A+6+10 starts at 17; promoting an ace would produce 27, so it stays hard 17. These calculations reuse `score_hand`; the new wrapper computes natural/pair facts from the actual card identities and split flag.

Equal-value is not equal-rank: J+K totals 20 but is not an equal-rank pair. Q+Q is. This matches the proposed **equal-rank split** rule. Pair detection alone does not authorize splitting: the future engine must also check round phase, split limits, split-ace rules and available virtual stake.

```sh
python3 - <<'PYCODE'
from public_game.cards import Card
from public_game.hands import hand_facts
hand = [Card('A', 'spades'), Card('K', 'hearts')]
print('Original hand:', hand_facts(hand))
print('After a split:', hand_facts(hand, from_split=True))
PYCODE
```

Both totals are 21; only the first is natural.
