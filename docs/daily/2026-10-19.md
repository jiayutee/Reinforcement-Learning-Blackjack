# 2026-10-19 — understand the table when you arrive

## 03:00 checkpoint: announce the first visible state

### Prerequisites

The Python session remains authoritative. The browser reads a JSON snapshot from `/state`, then displays cards and status. The previous lesson added a polite `aria-live` status message after accepted actions. This lesson adds the same summary on initial page load, including when returning to a game that is already in progress.

### Intuition

When someone opens or reloads the page, the cards may already be dealt. A sighted user can scan the table, but a screen-reader user needs the current turn described. The first successful state read should therefore provide context. Later Refresh clicks should not repeat a long hand summary; they keep the shorter “State refreshed” message.

### Rule and worked example

```text
first successful state read or accepted action -> announce that snapshot
later read-only refresh -> “State refreshed.”
```

For example, reconnecting at revision 2 to Hand 1, Hard 15, with the dealer showing a 9 and actions Hit/Stand should say: “Hand 1. Hard total 15. Dealer shows 9 of hearts. Available actions: hit, stand.” This description comes from the returned snapshot. The browser does not infer the next action or change any rewards.

### Code walkthrough

In [the local table](../../public_game/local_game.html), `hasLoaded` starts false. On a successful response, the page uses `stateAnnouncement(data)` if the request is a command or if no successful state has yet loaded. It then marks `hasLoaded` true. A later GET uses the neutral refresh message. A rejected response does not set `hasLoaded`, so an eventual successful read still gives the user context. Sound remains tied only to accepted game commands; the initial GET and reconnect do not make a sound.

## 04:00 checkpoint: landmarks and named control groups

### Prerequisites and intuition

HTML elements expose roles to assistive technology. A `<main>` landmark gives users a direct way to jump to the primary content, while a named `role="group"` lets them identify related controls without depending on visual position. The page had native buttons, but the hand actions and sound settings were not grouped by name.

### Worked example

The game now exposes one main landmark and two named groups: **Hand actions** and **Sound settings**. A browser accessibility query should find exactly one of each. When keyboard or screen-reader users navigate by landmarks, the table and its controls are easier to locate.

### Code and experiment

In [the table HTML](../../public_game/local_game.html), a `<main>` wraps the wager, action controls, feedback, table and state inspector. The action buttons and sound controls are wrapped in named groups. The controls remain native buttons and labelled inputs, so no custom keyboard implementation was introduced.

The Chrome gate in [`tests/browser/public-game.cjs`](../../tests/browser/public-game.cjs) queries the accessibility roles and names, then runs the existing Deal, split, ace, outcome, sound and mobile journeys. ## 05:00 checkpoint: disclose the playable rules

### Prerequisites and intuition

The browser page now supports deals, hits, stands, doubles and splits. Before a player wagers virtual chips, they should be able to inspect the rules that determine those actions and payouts. A native collapsed `<details>` disclosure keeps the compact table readable while remaining keyboard-operable.

### Worked payout example

The public profile pays a natural blackjack 3:2. If the initial wager is 10 chips, the net win is `10 × 3/2 = 15` chips (the wager is returned too). Equal opening naturals push, while a 21 made after splitting receives the ordinary 1:1 win. This is why a rule summary must distinguish natural blackjack from any other 21.

### Coding walkthrough

The **Game rules** disclosure in [the local table](../../public_game/local_game.html) lists the six-deck shoe, dealer standing on soft 17, natural/split-21 payouts, double/split restrictions, and unavailable insurance/surrender. It is presentation only: the Python contract remains authoritative in [`public-round-v1.md`](../decisions/public-round-v1.md). The browser gate opens the disclosure and asserts the rule phrases, alongside the existing main landmark and named groups.
