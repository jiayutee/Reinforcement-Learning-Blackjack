## Start with your policy question

A **policy** is the rule choosing an action from an observation. These two policies are fixed:

| Player total | Random policy | Threshold-17 policy |
|---|---|---|
| 12 | Hit or stand, each with probability 1/2 | Hit |
| 16 | Hit or stand, each with probability 1/2 | Hit |
| 20 | Hit or stand, each with probability 1/2 | Stand |

Run them from the project folder:

```sh
python3 -m foundations.play --policy random --episodes 3 --seed 7
python3 -m foundations.play --policy threshold --episodes 3 --seed 7
```

`--policy` is a command-line option: the program reads the following word and selects that decision rule. `random` ignores the cards when choosing an action. `threshold` reads the player's total but does not use the dealer's upcard. Neither rule updates itself from experience.

## What actually learns in Lesson 2?

The Monte Carlo estimator collects completed hands and learns **how good a position is under the chosen policy**. The policy continues choosing the same way.

Suppose a position is seen in four different hands. The later outcomes are `+1, -1, 0, +1`. Its estimated value becomes:

```text
V = (1 - 1 + 0 + 1) / 4 = 0.25 units
```

That means estimated net return, not a 25% win rate. In this example, two of four hands won: the sample win rate is 50%.

The incremental update produces the same average without storing all returns:

```text
N <- N + 1
V <- V + (new return - V) / N
```

After the first three outcomes, N is 3 and V is 0. The fourth outcome increases N to 4 and changes V to `0 + (1 - 0)/4 = 0.25`. For the full explanation, read [Lesson 2](../lessons/02-monte-carlo-prediction.md) and run:

```sh
python3 -m foundations.monte_carlo --episodes 10000 --seed 7 --trace
```

Later, action values `Q(s, hit)` and `Q(s, stand)` will help change the policy. First, we are checking that the environment generating the experiences follows the intended rules.

Different random generators and reset draw order mean a shared seed would not produce identical games across implementations. The statistical check instead uses five independently seeded streams per policy and implementation: 20,000 hands each, **400,000 hands total**.

| Policy | Foundations mean return | Gymnasium mean return | Difference |
|---|---:|---:|---:|
| random | -0.39351 | -0.39311 | -0.00040 |
| threshold | -0.07941 | -0.08293 | +0.00352 |

Each table entry combines 100,000 hands. These are observed averages, not a claim of policy optimality or positive expected profit.

For individual seed comparisons, the largest absolute difference was approximately **0.0259** units/hand, with a difference standard error of approximately **0.0094**. A standard error describes sampling variability of a mean; it is not the variability of one hand. We report the differences instead of declaring an arbitrary statistical pass. Multiple comparisons and finite samples mean these measurements are not a formal equivalence proof.

The checker uses separate action randomness for the random policy (`agent seed = environment seed + 2,000,000`). Reference environment seeds are local seeds plus 1,000,000. Consequently its random-policy samples need not exactly reproduce the separate `foundations.play` CLI, even though both use 50/50 decisions.

The code's observation/reward rules matched the tested cases. This does not prove identical behavior for every possible state, invalid action, post-terminal call, API signature, or rendering feature. No changes to gameplay or existing learning code were needed.
