# 2026-10-23 — test the exact bankroll boundary

## 03:00 checkpoint: afford a wager equal to the balance

### Prerequisites and intuition

The input is in whole chips, while the session balance uses integer half-chip units. As in yesterday's lesson, multiply a whole-chip wager by two before comparing it with the balance. Today's small test isolates the boundary case: a player may commit the entire available balance to the initial wager, so equality must count as affordable.

### Equation and worked example

```text
affordable(w, B) = (2 × w <= B)
```

If the player has 20 half-chip units (10 whole chips), `w=10` costs exactly 20 units and is allowed. `w=11` costs 22 units and is not allowed. The correct comparison is `<=`; using `<` would incorrectly reject an exact-balance wager.

### Coding walkthrough

The browser test in [`public-game.cjs`](../../tests/browser/public-game.cjs) temporarily changes only its in-page snapshot to `balance: 20`, checks the four preset disabled states, then checks the exact 10-chip wager and the one-chip-over 11-chip wager. The original snapshot is restored before the server-backed play journey. This specifically tests that UI affordance boundary; Python still validates the actual request.
