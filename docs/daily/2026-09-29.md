# 29 September: does one good SARSA run repeat?

Today's lesson consolidates [SARSA](../lessons/05-sarsa.md) through a reproducible experiment. Prerequisites: a seed fixes a pseudorandom sequence; training changes Q; evaluation freezes Q. A mean is a sum divided by the number of observations. Review Lesson 5's equations if the learning update is still unfamiliar.

## Intuition

One successful run may depend on favorable training experience or favorable evaluation hands. Repeat training with several seeds while keeping the rules, learning rates, hand budgets, and evaluation procedure unchanged. This checks sensitivity without selecting only the best result.

SARSA still learns from `reward + Q(next state, selected next action)` before the episode finishes. Evaluation disables exploration and uses a frozen greedy policy, so it measures a different choice rule from training behavior.

## Fixed experiment and measured results

Five training seeds: 7, 19, 42, 101, 2026. Each trains for 50,000 hands with alpha=0.1 and epsilon=0.1. Each policy is evaluated for 20,000 hands with environment seed 1,000,000 + training seed. All settings match yesterday's first experiment; no retuning was performed.

The mean difference against threshold is -0.06249 - (-0.07970) = **+0.01721 reward units per hand** in this experiment. Both means remain negative. Seed 7 repeats yesterday's sample and is counted once here. Totals: 250,000 training hands and 300,000 evaluation hands across three policies.

## Work through the summary

For five run means m₁,…,m₅:

1. Average: m̄ = (m₁ + m₂ + m₃ + m₄ + m₅) / 5.
2. Deviation for run i: dᵢ = mᵢ - m̄.
3. Sample variance across runs: s² = (d₁² + … + d₅²) / (5 - 1).
4. Sample standard deviation: s = square root of s².

For SARSA, s is about **0.006905**. This describes the spread of these five run means. It combines training variation and evaluation sampling noise because both seeds change. It is not a confidence interval and does not measure the uncertainty of an individual hand.

Each exported evaluation also has an approximate interval computed from that frozen policy's sampled rewards. That interval does not include uncertainty from learning a different Q table. Repeating evaluation on one table alone would not test training-seed variation.

## Coding: reproduce without new infrastructure

From the project root, run this shell loop. The Python CLI handles training, freezes Q, and evaluates each policy; the loop changes only seeds and output filenames.

```sh
for seed in 7 19 42 101 2026; do
  python3 -m foundations.sarsa --episodes 50000 --eval-episodes 20000     --seed "$seed" --eval-seed "$((1000000 + seed))"     --epsilon 0.1 --alpha 0.1 --output "/tmp/sarsa-$seed.json"
done
```

Then summarize with the standard library:

```sh
python3 - <<'PYCODE'
import json
import statistics
from pathlib import Path
means = []
for seed in (7, 19, 42, 101, 2026):
    report = json.loads(Path(f"/tmp/sarsa-{seed}.json").read_text())
    greedy = next(row for row in report['evaluation'] if row['policy'] == 'greedy')
    means.append(greedy['mean_return'])
print('mean:', statistics.mean(means))
print('sample SD:', statistics.stdev(means))
PYCODE
```

`json.loads` reads the saved experiment, `next` selects the named evaluation, and the list keeps one mean per training seed. `statistics.stdev` uses the sample denominator n-1. No new learning algorithm is introduced in this checkpoint.

## What we can say

Greedy SARSA outperformed threshold in all five recorded runs. This is encouraging replication, not proof of optimality or a universal advantage. Only five training seeds were tested, evaluation seeds have been used in earlier project experiments, and the simplified rules exclude the public game's finite shoe and extra actions. Equal evaluation seeds do not imply identical hands across policies: different actions consume different draws. This is not a paired-hand experiment or a new untouched final benchmark. Avoid choosing parameters based on these results and then presenting the same data as an independent final test.
